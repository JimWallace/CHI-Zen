# Why \LaTeX?

\LaTeX\ is far from a perfect writing tool. For one thing, it's a *typesetting environment* and not a word processor, so little things like the difference between a \` and a ' can end up being a distraction. That is, when you're writing a paper, you generally want to focus on your words, and not getting the syntax right. So why use \LaTeX?

1. Formatting is done `for free' by the SIG CHI template, and it does a great job of this for you, so you can spend your time thinking about *what* you say, not how it should look.
2. The University of Waterloo provides a Pro Overleaf account if you login with your UW userid. Overleaf is lightweight, easy-to-use, and supports collaborative writing really well. 
3. \LaTeX\ integrates well with other (free) tools like R and Python, and any referencing software you can find through the Bib\TeX package.

However, as hinted at above, \LaTeX\ also isn't perfect, and so this project embodies some examples, tips, and hacks that make our typical publication workflow a little easier. For instance, I've included some supports for all of the following tasks:

1. Writing: It supports Markdown: enabling you to focus on *content*, and the ACM templates to handle all formatting

2. Collaborative Editing: Sections are separated out into files, so that authors can edit each one without interrupting one another on Overleaf, without the need to email drafts back and forth between authors, and with features like version control, and automatic backups. 

3. Illustrating: Several commonly-used \LaTeX\ packages are automatically included, for tasks like creating figures and tables, documenting code, and referencing

4. Revising: The \texttt{changes} package helps authors to show revisions to their work when working within the ACM's Revise \\& Resubmit model

5. Many (optional) in-text shortcuts are also included, for tasks like reporting statistics, defining colour palettes, and including alternative languages. They are there if you need them, and easy to ignore if you don't. 



## Markdown
A common complaint about \LaTeX\ is that it's hard to read and write, and that the learning curve is *really* steep. For this reason, we're following the general philosophy of letting \LaTeX\ handle the stuff it's good at --- formatting, math, figures, references --- and writing the rest in Markdown. Markdown is extremely easy to read and write. In fact, you're probably familiar with much of its syntax already: 

>    "The overriding design goal for Markdown’s formatting syntax is to make it as readable as possible. The idea is that a Markdown-formatted document should be publishable as-is, as plain text, without looking like it’s been marked up with tags or formatting instructions. While Markdown’s syntax has been influenced by several existing text-to-HTML filters, the single biggest source of inspiration for Markdown’s syntax is the format of plain text email"
> --- John Gruber \citep{gruber2006}.

However, you should be aware of some its limitations --- especially for some of the more technical aspects of a scientific paper. It doesn't always play well with tables, and while you can include images, Markdown doesn't necessarily offer some of the nice features that \LaTeX\ does. Keep reading for more information on that. 

**This template has been configured to allow *both* Markdown and \LaTeX\ syntax in the same file**, through the \texttt{markdown} package's \texttt{hybrid} option. You can even combine them in the same *sentence*, and for example write paragraphs in Markdown that include BibTeX citations.



## PGFPlots and My Templates 
As as I was completing my PhD, I decided to spend some time trying to learn to make better figures since this was something I expected to spend a lot of time doing over the rest of my career. Some of the things I'd hoped to improve on were using scalable graphics, having better control over the width/height of figures, and being able to use the data itself to create the images (better fit with a typical academic workflow). I also prefer a minimalist feel, and wanted my papers to reflect that (And even if you prefer something different, this is a good starting point, you can always make things more complex where needed). 

So after doing some research, I found that \texttt{PGFPlots} was a good fit for my needs. But it wasn't perfect, and in particular can be complicated to get right. So in the interest of saving the time of re-inventing the wheel, and (hopefully) enabling others to use my work for their own papers, I decided to create a set of templates that would encapsulate the common types of graphs I use in HCI research. I called these templates \texttt{IDEA Plots} after my lab at the time. As I developed the templates, they grew to include style choices, colour palettes, and some common shortcuts for layout. I expect they'll continue to evolve for a while to come.  

All of the examples in this document use those templates, which are now wrapped into CHI Zen, with some in-place customization based on the needs of the graph. 



## Tracking Changes

Since SIG CHI has begun transitioning its conferences to the *Proceedings of the ACM* model, most involve some form of Revise \\& Resubmit. That is, you should expect to take reviewer feedback into consideration and submit an updated version of your paper for a second round of review. When doing so, conferences typically ask for a marked-up version of the paper that shows where changes have been made.  To track changes in \LaTeX, we use the \texttt{changes} package. It provides a few simple functions to track anything that you've \texttt{added()}, \texttt{deleted()}, or \texttt{replaced} in the paper.

\subsection{Overleaf Settings}
\label{sec:overleaf}

CHI Zen uses the \texttt{acmart} class that comes with TeX Live (it is no longer copied into the project), and its documents produce a tagged, accessible PDF. Set these once per Overleaf project, under Menu, Settings:
\begin{itemize}
    \item \textbf{Compiler: LuaLaTeX.} The \LaTeX\ tagging code and \texttt{acmart} need LuaLaTeX for a fully tagged PDF. pdfLaTeX still compiles the documents, but the tags are less complete.
    \item \textbf{TeX Live version: 2026 or later.} On an older TeX Live, comment out the \texttt{\textbackslash DocumentMetadata} block at the top of the main file.
    \item \textbf{Main document:} \texttt{00-my-new-paper.tex} for your paper, or \texttt{CHIZen-Manual.tex} for this manual (formerly \texttt{CHIZen-Manual-chi2022.tex}).
\end{itemize}
With LuaLaTeX, shell escape is not needed (\texttt{minted} runs \texttt{latexminted}, which TeX Live allows, and \texttt{markdown} runs its Lua code directly); pdfLaTeX needs it for \texttt{markdown}, and Overleaf turns it on anyway. References use Bib\TeX\ with ACM's \texttt{ACM-Reference-Format} style and \texttt{natbib} (loaded by \texttt{acmart}), as ACM's TAPS expects; Overleaf runs Bib\TeX\ automatically. The \texttt{latexmkrc} file sets the same options for local builds with \texttt{latexmk}.

\subsection{Accessibility}
\label{sec:accessibility}

Accessibility used to be a perennial to-do item for \LaTeX\ papers: the \texttt{accessibility} package never worked with this template, and the SIGCHI guide had no \LaTeX\ advice beyond figure descriptions. That has changed. The \LaTeX\ Project's tagging project now produces tagged PDF, and \texttt{acmart} supports it (since v2.17). CHI Zen turns it on for you.

\paragraph{What CHI asks for.} The CHI 2027 publication formats page states that ``The CHI conference committee requests that authors ensure basic accessibility of their submissions'', and points to the SIGCHI \href{https://sigchi.org/resources/guides-for-authors/accessibility/}{Accessibility Guide for Authors} (last updated 2024-08-15). For the camera-ready version, CHI 2025 told authors that ``An external provider will tag TAPS-produced PDFs for accessibility; however, authors must provide meaningful alt text for figures in their source files and on PCS.'' The SIGCHI guide's rules are:
\begin{itemize}
    \item ``Mark up content such as headings and lists'': use \texttt{\textbackslash section}, \texttt{itemize}, \texttt{enumerate}, \texttt{figure} and \texttt{table}, not bold text or manual numbering.
    \item ``Provide a text description for all figures.'' In \LaTeX, ``you can use the \texttt{\textbackslash Description\{...\}} tag to add an image description.'' ``Figure descriptions are different to figure captions'': they ``are an alternative to seeing the figure'' and should not ``simply repeat the caption.'' The SIGACCESS \href{https://www.sigaccess.org/welcome-to-sigaccess/resources/describing-figures/}{Guide to Describing Figures} explains how to write them.
    \item ``Don't rely only on colour'': in figures and legends, ``use different shapes and patterns to provide another way to visually distinguish elements.''
    \item ``Create every table as a real table, not an image, and indicate which cells are headers.''
    \item ``Create every equation as a marked-up equation, not an image of an equation.''
    \item ``Set the metadata of your document'': its title and language.
\end{itemize}

\paragraph{What CHI Zen does.} The first line of \texttt{00-my-new-paper.tex} is a \texttt{\textbackslash DocumentMetadata} block that asks for a tagged PDF meeting PDF/UA-2 (the accessibility standard) and PDF/A-4f (the archival standard), in English. Compile with LuaLaTeX on TeX Live 2026 or later (on Overleaf: Menu, Settings, Compiler). The PDF then gets its headings, lists, tables, links, title and language tagged automatically, and the title you give \texttt{\textbackslash title} becomes the document title that screen readers announce. Note the difference: PDF/UA is about \emph{access}, PDF/A about \emph{preservation}; a PDF/A file is not accessible unless it is also tagged.

\paragraph{What you still have to do.}
\begin{enumerate}
    \item \textbf{Describe every figure.} Put \texttt{\textbackslash Description\{...\}} as the first line of each \texttt{figure} and \texttt{figure*}. \texttt{acmart} sends it to TAPS for the HTML version; CHI Zen also uses it as the PDF alt text of the first picture in that figure. Write it from the data: the chart type, the axes and their ranges, and the values or trends a reader needs (every figure in this manual has one; look at the source of \autoref{fig:bargraph}). If a figure has a picture but no description, the log shows a \texttt{CHIZen Warning}.
    \item \textbf{Mark the header rows of tables.} \texttt{acmart} assumes the first row of a \texttt{tabular} holds the column headers. If your table has two header rows, say so before it with \texttt{\textbackslash tagpdfsetup\{table/header-rows=\{1,2\}\}}. Keep every row the same width: add empty cells (\texttt{\&}) rather than ending a row early.
    \item \textbf{Write meaningful link text}, such as ``the \href{https://sigchi.org/resources/guides-for-authors/accessibility/}{SIGCHI Accessibility Guide}'' rather than ``click here''.
    \item \textbf{Get it right in black and white}: pair colour with labels, shapes or patterns, and check contrast.
    \item \textbf{Avoid subfigures} (\texttt{subcaption}) if you need a fully valid PDF/UA file: the tagging project lists \texttt{subcaption} as not yet compatible, and figures with subfigures fail PDF/UA validation, so this manual shows related plots as separate figures. Packages such as \texttt{minted} (code) and \texttt{changes} (tracked changes) compile but are not yet tagged meaningfully.
    \item \textbf{Check the PDF.} The free \href{https://verapdf.org}{veraPDF} validator checks PDF/UA and PDF/A, and this repository's GitHub workflow runs it on every push. A validator cannot judge whether a description is useful: read your descriptions aloud, or listen to the paper with a screen reader.
\end{enumerate}
